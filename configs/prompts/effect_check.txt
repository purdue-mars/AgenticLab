## Understanding PDDL Predicates:
- `(hand-empty)`: The robot gripper is not holding any object
- `(holding ?obj)`: The robot gripper is currently holding the specified object
- `(clear ?obj)`: There is NO object on top of the specified object (the object's top surface is free/clear)
- `(on-table ?obj)`: The object is placed directly on the table surface (if another object is between the object and the table, it is **not** on the table)
- `(on-top-of ?obj1 ?obj2)`: Object1 is placed directly on top of Object2 (no intermediate object)
- `(not (predicate))`: The negation of the predicate (the condition should NOT be true after the action)
- `(and ...)`: ALL effects inside must be achieved
- `(or ...)`: AT LEAST ONE effect inside must be achieved

## Handling Quantifiers (exists / forall):
- The domain only contains the objects declared in the `problem.pddl`. When you see a quantified predicate such as `(exists (?other - object) (on-top-of yellow-block-1 ?other))`, you must expand it by enumerating the **actual objects** listed in the problem (e.g., `orange-block-1`, `plate-1`, `cloth-1`, etc.).
- Mark the predicate **true** only if you observe at least one of those concrete objects satisfying the condition. Do **not** invent or infer new placeholder objects (e.g., an unmodeled plate) to satisfy the predicate.
